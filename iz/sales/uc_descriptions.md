# Етап 2. Описи UC6–UC9

## UC6 «Видати резерв»

| Поле | Значення |
|---|---|
| Актор | Фармацевт |
| Тригер | фармацевт вводить код, який назвав покупець |
| Передумови | резерв існує в аптеці фармацевта |
| Постумови | створено чек; резерв видано; заблоковану кількість списано |
| Зв'язки | використовує інтерфейс підсистеми «Резервування»; для рецептурного резерву виконує UC9 |

Нормальний потік: система знаходить фармацевта й резерв, перевіряє аптеку, стан та строк, за потреби
перевіряє і погашає рецепт, створює продаж, доручає `ReservationProvider` завершити видачу та зберігає
чек однією транзакцією.

| Потік | Умова | Реакція |
|---|---|---|
| 3a | код не знайдено | відмова без змін |
| 3b | резерв належить іншій аптеці | відмова без розкриття деталей продажу |
| 4a | стан не «Готове» і не «Продовжене» | відмова зі станом |
| 4b | строк дії минув | відмова, резерв і залишок не змінено |
| 5a | рецепт не дозволяє зарезервовану кількість | відмова |
| 6a | реєстр недоступний | транзакція відкочується |

## UC7 «Продати за е-рецептом»

| Поле | Значення |
|---|---|
| Актори | Фармацевт, Реєстр е-рецептів |
| Тригер | фармацевт вводить номер рецепта |
| Передумови | фармацевт автентифікований |
| Постумови | рецепт погашено, залишок списано, чек збережено |
| Зв'язки | `include UC9` |

Нормальний потік: UC9 повертає чинний рецепт, система перевіряє кількість, добирає партію FEFO,
погашає рецепт, застосовує реімбурсацію, створює продаж і зберігає всі зміни транзакційно.

| Потік | Умова | Реакція |
|---|---|---|
| 3a | рецепт не знайдено | відмова |
| 3b | рецепт прострочено, погашено або скасовано | відмова з причиною |
| 4a | кількість перевищує призначену | відмова |
| 5a | придатної партії немає | відмова та, якщо можливо, перелік інших аптек |
| 6a | реєстр недоступний | продаж не оформляється |

## UC8 «Продати безрецептурний препарат»

| Поле | Значення |
|---|---|
| Актор | Фармацевт |
| Тригер | фармацевт обирає препарат і кількість |
| Передумови | препарат існує в каталозі |
| Постумови | партію списано за FEFO, чек збережено |

Нормальний потік: система перевіряє тип препарату та ліміт, добирає непрострочену партію з
найближчим строком, створює чек і атомарно списує кількість.

| Потік | Умова | Реакція |
|---|---|---|
| 3a | препарат не знайдено | відмова |
| 3b | препарат рецептурний | відмова з вимогою виконати UC7 |
| 4a | перевищено ліміт одного чека | відмова з допустимим лімітом |
| 5a | придатної партії недостатньо | відмова без часткового продажу |

## UC9 «Перевірити е-рецепт»

| Поле | Значення |
|---|---|
| Клієнти | UC2, UC6, UC7 |
| Зовнішня система | Реєстр е-рецептів |
| Передумови | передано номер рецепта і поточну дату |
| Постумови | повернуто чинний рецепт або типізовану причину відмови |

Нормальний потік: сервіс звертається до реєстру, перевіряє наявність, стан, дату виписки, 30-денний
строк та, для UC2/UC6, відповідність МНН препарату.

| Потік | Умова | Реакція |
|---|---|---|
| 2a | реєстр недоступний | клієнту повертається контрольована відмова |
| 3a | номер не знайдено | відмова |
| 3b | рецепт не активний або прострочений | відмова з причиною |
| 6b | МНН не відповідає препарату | відмова для підсистеми резервування |
