# Етап 1. Вимоги підсистеми «Склад і звітність»

## Призначення і межі

Підсистема веде облік партій аптеки: приймає поставки постачальників, списує партії з причиною,
попереджає про строки придатності й будує звіт про продажі. Вона не оформлює продаж і не змінює
резервування: чеки читає з підсистеми «Продаж» лише для звіту, а зарезервовану кількість списати не
дозволяє.

| Стейкхолдер | Інтерес |
|---|---|
| Завідувач аптеки | точні залишки, контроль строків, документований облік списань |
| Директор мережі | звіт про продажі всіх аптек для порівняння |
| Постачальник | відображення накладної в залишках аптеки |
| Фармацевт | достовірний залишок і партії для FEFO |
| Підсистема «Резервування» | зарезервована кількість не зникає внаслідок списання |

## Деталізовані вимоги

Вимоги мають атрибут `subsystem: Склад і звітність` у `lab1/srs.yaml`.

| ID | Короткий зміст | Пріоритет |
|---|---|---|
| R9 | реєструвати поставку партій | 2 |
| R9.1 | відмовляти в повторній накладній | 2 |
| R9.2 | відмовляти в простроченій позиції, нульовій кількості, дублі серії | 2 |
| R9.3 | приймати поставку цілою транзакцією | 2 |
| R10 | списувати партію з причиною | 3 |
| R10.1 | списувати лише вільний залишок | 2 |
| R10.2 | зберігати акт списання з причиною зі списку | 3 |
| R11 | звіт про продажі за період | 3 |
| R11.1 | завідувач бачить свою аптеку, директор — усі | 3 |
| R11.2 | період включає обидві межові дати повністю | 3 |
| R13 | попередження про строки до 30 днів | 3 |
| R13.1 | у переліку також прострочені партії із залишком | 3 |

Числові межі для тестування: строк придатності позиції 0/1 день, залишок для списання 20/21 з 20,
горизонт попередження 30/31 день, межі періоду звіту 00:00:00 і 23:59:59 крайніх днів.
