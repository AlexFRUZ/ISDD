# Етап 2. Описи варіантів використання підсистеми «Резервування»

Межі TUCBW і TUCEW записано у файлі `lab3/use_cases.yaml`.

## UC2 «Зарезервувати препарат»

| Поле | Значення |
|---|---|
| **ID / важливість** | UC2 / висока |
| **Основний актор / тип** | Покупець / детальний, суттєвий |
| **Стейкхолдери** | Покупець: отримати гарантію наявності. Завідувач аптеки: контроль залишків. |
| **Тригер / тип** | покупець обирає аптеку й кількість / зовнішній |
| **Зв'язки** | асоціація: Покупець; include: UC9; extend: UC1 |
| **Передумови** | препарат і аптека існують |
| **Постумови** | створено резервування у стані «Підтверджене», доступний залишок зменшено |

**Нормальний потік.**

1. Покупець обирає препарат, аптеку й кількість.
2. ІС перевіряє кількість.
3. ІС перевіряє ліміт активних резервувань покупця.
4. ІС добирає партію з найближчим строком придатності.
5. Якщо препарат рецептурний, include UC9: ІС перевіряє рецепт.
6. ІС створює резервування й блокує залишок партії.
7. Покупець отримує код резервування зі строком дії.

| Потік | Умова | Реакція |
|---|---|---|
| 3a | покупець уже має 3 активні резервування | відмова, зміни не вносяться |
| 4a | кількість поза межами 1..6 | відмова з межами |
| 5a | немає придатної партії | відмова |
| 6a | рецепт потрібен, але номер не вказано | відмова |
| 6b | рецепт не підходить | відмова |

## UC3 «Скасувати резервування»

| Поле | Значення |
|---|---|
| **ID / важливість** | UC3 / середня |
| **Основний актор / тип** | Покупець / детальний, суттєвий |
| **Стейкхолдери** | Покупець: звільнити товар. Завідувач аптеки: повернути залишок у продаж. |
| **Тригер / тип** | покупець відкриває своє резервування / зовнішній |
| **Зв'язки** | асоціація: Покупець |
| **Передумови** | резервування існує |
| **Постумови** | стан «Скасоване», залишок повернуто |

**Нормальний потік.**

1. Покупець обирає резервування.
2. ІС перевіряє, що воно належить покупцю.
3. ІС перевіряє, що воно активне.
4. ІС скасовує резервування й повертає залишок.
5. Покупець бачить підтвердження.

| Потік | Умова | Реакція |
|---|---|---|
| 3a | резервування не знайдено або воно чуже | відмова без розкриття чужих даних |
| 3b | резервування вже завершене | відмова зі станом |

## UC4 «Підготувати резерв»

| Поле | Значення |
|---|---|
| **ID / важливість** | UC4 / середня |
| **Основний актор / тип** | Фармацевт / детальний, суттєвий |
| **Стейкхолдери** | Фармацевт: бачити, що зібрати. Покупець: дізнатися про готовність. |
| **Тригер / тип** | фармацевт відкриває нове резервування / зовнішній |
| **Зв'язки** | асоціація: Фармацевт, SMS-шлюз |
| **Передумови** | фармацевт працює в аптеці резервування |
| **Постумови** | стан «Готове», зафіксовано факт сповіщення |

**Нормальний потік.**

1. Фармацевт відкриває резервування за кодом.
2. ІС перевіряє фармацевта й аптеку.
3. Фармацевт збирає препарат.
4. ІС переводить резервування у стан «Готове».
5. ІС надсилає сповіщення покупцю.

| Потік | Умова | Реакція |
|---|---|---|
| 3a | резервування не знайдено | відмова |
| 3b | резервування іншої аптеки | відмова |
| 4a | стан не «Підтверджене» | відмова зі станом |
| 5a | SMS-шлюз недоступний | резерв готовий, зафіксовано, що сповіщення не надіслано |

## UC5 «Продовжити резервування»

| Поле | Значення |
|---|---|
| **ID / важливість** | UC5 / низька |
| **Основний актор / тип** | Фармацевт / детальний, суттєвий |
| **Стейкхолдери** | Покупець: забрати препарат пізніше. Завідувач аптеки: продовження лише один раз. |
| **Тригер / тип** | покупець просить продовжити резерв / зовнішній |
| **Зв'язки** | асоціація: Фармацевт |
| **Передумови** | фармацевт працює в аптеці резервування |
| **Постумови** | стан «Продовжене», строк дії більший на 24 години |

**Нормальний потік.**

1. Фармацевт вводить код резервування.
2. ІС перевіряє фармацевта й аптеку.
3. ІС перевіряє, що резервування готове.
4. ІС додає 24 години.
5. Фармацевт бачить новий строк.

| Потік | Умова | Реакція |
|---|---|---|
| 3a | резервування не знайдено | відмова |
| 3b | резервування іншої аптеки | відмова |
| 4a | резервування вже продовжено | відмова |
| 4b | резервування ще не готове або завершене | відмова зі станом |
