# Специфікація вимог до ПЗ: ІС «Мережа аптек»

## 1. Вступ

**Проєкт:** ІС «Мережа аптек».

**Спонсор:** директор мережі аптек.

**Бізнес-потреба:** Мережі потрібен єдиний облік залишків і формалізоване резервування, щоб зменшити навантаження на фармацевтів, прибрати подвійне введення рецептів і скоротити втрати через прострочення партій.

## 2. Загальний опис

### 2.1 Функції продукту

- R1: ІС повинна надавати покупцю пошук препаратів у наявності за торговою або міжнародною непатентованою назвою.
- R2: ІС повинна дозволяти покупцю резервувати препарат у вибраній аптеці.
- R3: ІС повинна дозволяти покупцю скасовувати власне активне резервування.
- R4: ІС повинна анулювати резервування, не видане протягом 24 годин від створення.
- R5: ІС повинна дозволяти фармацевту видавати зарезервований препарат за кодом резервування.
- R6: ІС повинна дозволяти фармацевту продавати препарат за електронним рецептом.
- R7: ІС повинна дозволяти фармацевту продавати безрецептурний препарат без рецепта.
- R8: ІС повинна відмовляти в продажу препарату з партії, строк придатності якої минув.
- R9: ІС повинна дозволяти завідувачу аптеки реєструвати поставку партій препаратів.
- R10: ІС повинна дозволяти завідувачу аптеки списувати партію із зазначенням причини.
- R11: ІС повинна формувати звіт про продажі аптек за вибраний період.
- R12: ІС повинна надсилати покупцю сповіщення про готовність резервування.
- R13: ІС повинна попереджати завідувача аптеки про партії, строк придатності яких завершується протягом 30 днів.

### 2.2 Користувачі

- Покупець
- Фармацевт
- Завідувач аптеки
- Директор мережі
- Реєстр е-рецептів (ЕСОЗ)
- SMS-шлюз

### 2.3 Обмеження

- обмін даними про рецепти лише через API реєстру ЕСОЗ
- обробка персональних даних відповідно до закону
- навчальний прототип реалізується мовою Python 3.10 або новішою

## 3. Специфічні вимоги

### 3.1 Функціональні вимоги

- **R1** *(пріоритет 1)*. ІС повинна надавати покупцю пошук препаратів у наявності за торговою або міжнародною непатентованою назвою.
  - **R1.1** *(пріоритет 1)*. ІС повинна показувати перелік аптек із доступним залишком і ціною препарату.
  - **R1.2** *(пріоритет 3)*. ІС повинна фільтрувати результати пошуку за містом.
  - **R1.3** *(пріоритет 2)*. ІС повинна пропонувати аналоги з тією самою міжнародною непатентованою назвою, якщо шуканого препарату немає в наявності.
- **R2** *(пріоритет 1)*. ІС повинна дозволяти покупцю резервувати препарат у вибраній аптеці.
  - **R2.1** *(пріоритет 1)*. ІС повинна відмовляти в резервуванні покупцю, який уже має 3 активні резервування.
  - **R2.2** *(пріоритет 1)*. ІС повинна приймати резервування лише на кількість від 1 до 6 упаковок.
  - **R2.3** *(пріоритет 1)*. ІС повинна зменшувати доступний залишок на зарезервовану кількість на час дії резервування.
  - **R2.4** *(пріоритет 2)*. ІС повинна вимагати номер чинного електронного рецепта для резервування рецептурного препарату.
  - **R2.5** *(пріоритет 2)*. ІС повинна закріплювати за резервуванням партію з найближчим строком придатності, залишковий строк якої становить не менше 30 днів.
- **R3** *(пріоритет 2)*. ІС повинна дозволяти покупцю скасовувати власне активне резервування.
- **R4** *(пріоритет 1)*. ІС повинна анулювати резервування, не видане протягом 24 годин від створення.
  - **R4.1** *(пріоритет 1)*. ІС повинна повертати кількість анульованого резервування до доступного залишку.
  - **R4.2** *(пріоритет 3)*. ІС повинна дозволяти фармацевту один раз продовжити резервування на 24 години.
- **R5** *(пріоритет 1)*. ІС повинна дозволяти фармацевту видавати зарезервований препарат за кодом резервування.
- **R6** *(пріоритет 1)*. ІС повинна дозволяти фармацевту продавати препарат за електронним рецептом.
  - **R6.1** *(пріоритет 1)*. ІС повинна перевіряти рецепт у реєстрі е-рецептів перед оформленням продажу.
  - **R6.2** *(пріоритет 1)*. ІС повинна відмовляти в продажу за рецептом, який не знайдено, скасовано, погашено або виписано понад 30 днів тому.
  - **R6.3** *(пріоритет 1)*. ІС повинна відмовляти в продажу кількості, що перевищує призначену в рецепті.
  - **R6.4** *(пріоритет 1)*. ІС повинна погашати рецепт у реєстрі під час оформлення продажу.
  - **R6.5** *(пріоритет 2)*. ІС повинна зменшувати до покупця суму чека на частку реімбурсації, вказану в рецепті.
- **R7** *(пріоритет 2)*. ІС повинна дозволяти фармацевту продавати безрецептурний препарат без рецепта.
  - **R7.1** *(пріоритет 1)*. ІС повинна відмовляти в продажу рецептурного препарату без електронного рецепта.
- **R8** *(пріоритет 1)*. ІС повинна відмовляти в продажу препарату з партії, строк придатності якої минув.
  - **R8.1** *(пріоритет 2)*. ІС повинна під час продажу добирати партію з найближчим строком придатності.
- **R9** *(пріоритет 2)*. ІС повинна дозволяти завідувачу аптеки реєструвати поставку партій препаратів.
- **R10** *(пріоритет 3)*. ІС повинна дозволяти завідувачу аптеки списувати партію із зазначенням причини.
- **R11** *(пріоритет 3)*. ІС повинна формувати звіт про продажі аптек за вибраний період.
- **R12** *(пріоритет 3)*. ІС повинна надсилати покупцю сповіщення про готовність резервування.
- **R13** *(пріоритет 3)*. ІС повинна попереджати завідувача аптеки про партії, строк придатності яких завершується протягом 30 днів.

### 3.2 Операційні вимоги

- **N4** *(пріоритет 3)*. ІС повинна працювати в браузерах Chrome, Firefox і Edge двох останніх версій.

### 3.3 Вимоги продуктивності

- **N1** *(пріоритет 1)*. ІС повинна показувати результати пошуку препарату не довше ніж за 2 с при 200 одночасних користувачах.
- **N2** *(пріоритет 2)*. ІС повинна оформлювати продаж не довше ніж за 5 с без урахування часу відповіді реєстру е-рецептів.
- **N3** *(пріоритет 2)*. ІС повинна бути доступною не менше 99,5 % часу протягом місяця.

### 3.4 Вимоги безпеки

- **N5** *(пріоритет 1)*. ІС повинна дозволяти оформлення продажу лише користувачам із роллю «фармацевт».

### 3.5 Культурні та політичні вимоги

- **N6** *(пріоритет 1)*. ІС повинна обробляти персональні дані покупців відповідно до Закону України про їх захист.

### 3.6 Обмеження проєктування

- **C1**. ІС повинна бути реалізована мовою Python 3.10 або новішою.
- **C2**. ІС повинна обмінюватися даними про рецепти лише через API реєстру ЕСОЗ.
- **C3**. ІС повинна використовувати SQLite як СУБД навчального прототипу.
